# Gitora — руководство пользователя

Gitora — десктопное приложение для работы с GitHub и визуального просмотра истории Git. В нём можно смотреть граф коммитов и веток, читать детали коммитов, создавать репозитории и ветки, работать с Pull Request и задачами, редактировать README и выпускать релизы.

Руководство соответствует интерфейсу Gitora **0.2** для Windows.

## Установка и первый запуск

1. Скачайте установщик Gitora из раздела [Releases проекта](https://github.com/Appappars/Gitora/releases).
2. Запустите файл `Gitora Setup 0.2.exe` и завершите установку.
3. Откройте Gitora.
4. Подключитесь с PAT по инструкции ниже.

Gitora работает как приложение Windows. Интернет нужен для обращения к GitHub API, загрузки истории, создания веток и остальных операций с репозиторием.

## Подключение GitHub

Единственный способ входа в Gitora — **Personal Access Token (PAT)**. Пароль от GitHub вводить в приложение не нужно: Gitora принимает токен и хранит его в защищённом системном хранилище Windows.

После запуска Gitora сразу открывает рабочее пространство или окно подключения с PAT — без дополнительных шагов и экранов знакомства.

### Создание Personal Access Token

1. В окне Gitora нажмите **Подключиться с PAT** или откройте **GitHub Settings → Tokens** в окне входа.
2. На GitHub откройте **Tokens (classic)**.
3. Нажмите **Generate new token → Generate new token (classic)**.
4. Укажите название, например `Gitora`.
5. Выберите срок действия токена.
6. Для полной работы Gitora включите права:

   | Право | Для чего нужно |
   |---|---|
   | `repo` | Репозитории, коммиты, ветки, README, Pull Request и задачи |
   | `read:user` | Чтение профиля и имени пользователя |
   | `delete_repo` | Удаление репозитория из Gitora |

7. Нажмите **Generate token** и сразу скопируйте токен. GitHub показывает его только один раз.
8. Вернитесь в Gitora, вставьте токен в поле **GitHub Personal Access Token** и нажмите **Подключить**.

![Создание токена GitHub](screenshots/github-classic-token.png)

Токен хранится в защищённом системном хранилище Windows и не показывается интерфейсу после входа.

## Главное окно

После входа Gitora загружает список репозиториев. Окно состоит из трёх основных частей:

1. **Левая панель** — аккаунт GitHub, список проектов и настройки.
2. **Верхняя часть проекта** — название репозитория, частые кнопки действий и статистика.
3. **Основная область** — поиск, вкладки **Граф**, **Pull Requests**, **Задачи** и содержимое выбранной вкладки.

![Gitora в светлой теме](screenshots/gitora-light-theme.png)

На узком экране левая панель открывается кнопкой меню в левом верхнем углу. Закрыть её можно кнопкой **Закрыть меню** или кликом по затемнённой области.

## Справочник кнопок

### Левая панель

| Кнопка или элемент | Действие |
|---|---|
| Профиль GitHub | Показывает подключённый аккаунт. Если GitHub не подключён, открывает окно входа. |
| **ПРОЕКТЫ** | Заголовок списка репозиториев. |
| **Добавить** рядом с «ПРОЕКТЫ» | Открывает **Новый репозиторий**. Доступно после входа. |
| Карточка репозитория | Выбирает репозиторий и загружает его данные. |
| Корзина на карточке | Открывает подтверждение удаления репозитория. Удаление на GitHub необратимо. |
| **Настройки** | Открывает тему, синхронизацию, лимит коммитов и параметры загрузок. |
| `⋯` внизу панели | Открывает **Обновления**, **Подключение к ИИ** и отключение GitHub. |
| **Подключиться с PAT** | Открывает окно ввода Personal Access Token, если GitHub ещё не подключён. |

### Панель проекта

| Кнопка | Действие |
|---|---|
| **Обновить** | Обновляет ветки, коммиты и граф текущего репозитория. |
| **Синхронизация** | Обновляет список репозиториев и данные выбранного проекта. |
| **Создать ветку** | Сразу открывает форму создания ветки от основной ветки. |
| `⋯` | Открывает README, изменения, релиз, редактирование, управление ветками, копирование ссылки и GitHub. |

Под кнопками отображается статистика: число коммитов, число веток и дата обновления репозитория.

### Поиск коммитов

- Поле **Поиск коммитов…** ищет по сообщению коммита.
- Кнопка `X` очищает запрос, автора и даты.
- Кнопка **Фильтры** раскрывает дополнительные поля:
  - **Автор** — GitHub username или имя автора;
  - **С даты** — начало периода;
  - **По дату** — конец периода.

Результаты обновляются автоматически после изменения запроса или фильтра.

### Вкладки проекта

| Вкладка | Что показывает |
|---|---|
| **Граф** | Историю коммитов, связи веток и слияния. |
| **Pull Requests** | Pull Request с фильтрами по состоянию. |
| **Задачи** | GitHub Issues с фильтрами по состоянию. |

В графе есть выпадающий список **Все ветки**. Управление ветками находится в меню `⋯` шапки проекта. В меню `⋯` вкладки графа можно скрыть или снова показать граф.

### Настройки

В окне **Настройки** доступны:

- **Синхронизировать сейчас** — немедленно обновить данные GitHub;
- **Светлая**, **Тёмная**, **Системная** — выбрать тему;
- **Лимит коммитов** — загружать 25, 50 или 100 коммитов;
- **Системная папка загрузок** — сохранять архивы в `Downloads`;
- **Спрашивать каждый раз** — выбирать папку перед каждой загрузкой;
- **Выбрать папку** и **Использовать** — назначить свою папку для архивов;
- **Сохранить** — применить настройки;
- **Отмена** или `X` — закрыть окно без применения несохранённых изменений.

### Обновления

В окне **Обновления**:

- **Скачать** — скачать `.exe` текущего релиза;
- кнопка с именем файла — скачать отдельный asset;
- **Все релизы на GitHub** — открыть страницу релизов проекта в браузере;
- `X` — закрыть окно.

## Работа с графом коммитов

1. Выберите репозиторий в левой панели.
2. Откройте вкладку **Граф**.
3. Выберите **Все ветки** или конкретную ветку.
4. Кликните по узлу коммита.
5. Справа или снизу появится панель **Детали коммита**.

В деталях отображаются сообщение, автор, дата, ветка и короткий хеш. Доступны действия:

- **Копировать хеш** — копирует полный SHA коммита;
- **Скачать эту версию** — скачивает архив состояния репозитория на выбранном коммите;
- **Открыть на GitHub** — открывает страницу коммита;
- `X` или клавиша `Esc` — закрывает панель деталей.

## Ветки

1. Откройте вкладку **Граф**.
2. Нажмите `⋯` в шапке проекта и выберите **Управление ветками**.
3. Во вкладке **Ветки (число)** можно увидеть все ветки.
4. Для создания откройте вкладку **Создать**.
5. Введите имя, например `feature/my-feature`, и нажмите **Создать**.

Новая ветка создаётся от базовой ветки, указанной в окне. В списке веток при наведении появляются действия:

- **Переименовать** — ввести новое имя и нажать **Переименовать**;
- **Удалить** — подтвердить удаление кнопкой **Удалить**.

Кнопка **Отмена**, `X` или клик по свободной области закрывает окно. Удаление ветки изменяет репозиторий на GitHub, поэтому проверяйте имя перед подтверждением.

## Pull Requests и задачи

### Pull Requests

1. Откройте вкладку **Pull Requests**.
2. Используйте фильтры **Открытые**, **Закрытые** или **Все**.
3. Нажмите **Создать PR**.
4. Заполните заголовок и описание.
5. Выберите **Из ветки** и **В ветку**.
6. Нажмите **Создать**.

Клик по Pull Request открывает его детали: статус, автора, направление веток и описание. Кнопка **Открыть на GitHub** показывает страницу PR в браузере. `X` закрывает детали.

### Задачи (Issues)

1. Откройте вкладку **Задачи**.
2. Выберите **Открытые**, **Закрытые** или **Все**.
3. Нажмите **Создать задачу**.
4. Укажите заголовок, описание и, при необходимости, метки через запятую, например `bug, enhancement`.
5. Нажмите **Создать**.

Клик по задаче показывает её статус, автора, метки, назначенных пользователей и описание. **Открыть на GitHub** открывает полную страницу issue.

## README, изменения и релизы

### README

В окне **README**:

1. Выберите ветку.
2. Измените Markdown в редакторе.
3. Напишите **Сообщение коммита**.
4. Нажмите **Сохранить**.

Кнопка **Отмена** закрывает редактор без сохранения. Если README ещё не существует, Gitora предложит создать его.

### Локальные изменения

Кнопка **Изменения** предназначена для проекта, который уже есть на диске:

1. Выберите ветку.
2. Нажмите **Выбрать папку проекта**.
3. Нажмите кнопку с обновлением **Проверить заново**, если файлы изменились после выбора папки.
4. Просмотрите счётчики добавленных, изменённых и удалённых файлов.
5. Введите **Сообщение коммита**.
6. Нажмите **Коммит и пуш**.

Кнопка отправляет изменения в выбранную ветку GitHub. Если изменений нет, папка не выбрана или сообщение пустое, кнопка будет недоступна.

### Релиз

В окне **Новый релиз**:

1. Введите тег, например `v1.0.0`.
2. Выберите ветку или укажите SHA в поле **Ветка или SHA**.
3. При необходимости укажите название и описание.
4. Нажмите **Прикрепить файл**, чтобы добавить asset.
5. При необходимости включите **Черновик** или **Pre-release**.
6. Нажмите **Создать**.

## Подключение ИИ через Gitora MCP

MCP позволяет подключить Gitora к ИИ-клиенту, который умеет работать с MCP. Например, Claude Desktop или Cursor смогут получать данные GitHub через уже открытую Gitora-сессию.

### Подключение через интерфейс Gitora

1. Откройте меню `⋯` внизу боковой панели и выберите **Подключение к ИИ**. Также раздел доступен из **Настроек**.
2. Выберите клиент: Claude Desktop, Cursor, Codex, ChatGPT или ручную настройку.
3. На шаге **Проверка** нажмите **Проверить подключение**. Gitora отдельно проверит файл MCP-сервера, локальный мост, GitHub-сессию, инструменты, репозитории, ветки, коммиты и детали тестового коммита.
4. Для Claude Desktop и Cursor можно нажать **Настроить автоматически**. Gitora добавит только сервер `gitora`, не удаляя другие серверы, и создаст резервную копию конфигурации.
5. Для остальных клиентов используйте **Копировать конфигурацию**, вставьте блок в MCP-настройки клиента и перезапустите его.
6. На шаге **Доступ** повторите проверку после перезапуска ИИ-клиента.

Статус подключения к ИИ открывается внутри этого раздела. Внизу мастера можно посмотреть журнал последних обращений без токенов и содержимого файлов.

### Перед подключением

1. Установите Gitora.
2. Запустите Gitora.
3. Подключитесь с PAT и убедитесь, что список репозиториев загрузился.
4. Установите Node.js, чтобы команда `node` была доступна в терминале.
5. Закройте и снова откройте ИИ-клиент после изменения его MCP-конфигурации.

Важно: MCP не заменяет Gitora. Gitora должна оставаться запущенной и авторизованной, потому что именно она выполняет запросы к GitHub через защищённый локальный мост.

### Подключение через настройки Gitora

Откройте **Настройки → Интеграции → Подключение к ИИ**. Нажмите **Подключить** рядом с Claude Desktop, Cursor или Codex. Gitora найдёт конфигурацию клиента, добавит только сервер Gitora и проверит сохранённые настройки.

После этого нажмите **Подключить сейчас**. Gitora перезапустит только локальный bridge и дождётся heartbeat MCP-клиента; статус **Подключено** появится после реального запроса от клиента через MCP. При первой регистрации нового MCP-сервера может потребоваться открыть новый чат.

Node.js и отдельная установка MCP-сервера не нужны: встроенный Electron runtime Gitora запускает `mcp-server.cjs` через stdio. Другие подключения в конфигурации клиента сохраняются.

Для неподдерживаемого клиента выберите **Настроить вручную**. Gitora покажет компактную готовую конфигурацию с уже определённым путём к установленному приложению и кнопкой копирования.

### Инструменты MCP

Основные инструменты чтения:

| Инструмент | Назначение |
|---|---|
| `list_repos` | Получить список репозиториев текущего GitHub-пользователя. |
| `get_commits` | Получить историю коммитов репозитория или ветки. |
| `get_branches` | Получить список веток и SHA их последних коммитов. |
| `get_commit_detail` | Получить детали коммита и список изменённых файлов. |
| `search_commits` | Найти коммиты по сообщению или автору. |

В текущей версии сервера также доступны операции для построения Git-истории:

| Инструмент | Назначение |
|---|---|
| `create_repo_file` | Создать первый файл и коммит в пустом репозитории. |
| `get_git_commit_object` | Получить raw Git commit object и SHA дерева. |
| `create_git_blob` | Создать Git blob. |
| `create_git_tree` | Создать Git tree. |
| `create_git_commit` | Создать Git commit. |
| `create_git_branch` | Создать ветку от SHA коммита. |
| `update_git_branch` | Переместить ветку на другой SHA без force push. |

Инструменты второй таблицы изменяют данные на GitHub. Просите ИИ сначала показать план и дождитесь проверки перед операциями записи.

## Проверка MCP

После перезапуска клиента отправьте ИИ по очереди:

1. **«Покажи список моих репозиториев через Gitora.»**
2. **«Покажи последний коммит репозитория `owner/repository`.»**
3. **«Покажи ветки репозитория `owner/repository`.»**

Для теста с проектом Gitora можно использовать:

```text
Покажи мои репозитории через Gitora MCP.
Покажи последний коммит Sabinchous/Gitora.
Покажи ветки Sabinchous/Gitora.
```

Чтобы ИИ работал с конкретным проектом, всегда указывайте владельца и название репозитория в формате `owner/repository`.

### Примеры запросов к ИИ

```text
Найди в Sabinchous/Gitora все коммиты, где упоминается MCP.
```

```text
Покажи детали коммита <SHA> в Sabinchous/Gitora и перечисли изменённые файлы.
```

```text
Сначала покажи план. Затем создай в Sabinchous/Gitora-Branch-Flow-Demo ветку feature/reports от main и подготовь три последовательных коммита. Перед каждой записью проверь текущий SHA ветки.
```

Последний пример использует write-инструменты. Для важных репозиториев сначала делайте пробу на тестовом проекте.

## Решение проблем

### GitHub не подключается

- Проверьте, что токен скопирован полностью и без пробелов.
- Убедитесь, что токен не просрочен.
- Для приватных репозиториев проверьте право `repo`.
- Если нужна кнопка удаления репозитория, проверьте право `delete_repo`.
- Создайте новый токен, если старый был отозван.

### Список репозиториев пуст

Нажмите **Обновить** или **Настройки → Синхронизировать сейчас**. Также проверьте, что подключён правильный GitHub-аккаунт и у токена есть доступ к нужным репозиториям.

### ИИ не видит Gitora MCP

1. Убедитесь, что Gitora запущена.
2. Убедитесь, что внутри Gitora выполнен вход в GitHub.
3. Откройте **Настройки → Интеграции → Подключение к ИИ** и проверьте статус клиента.
4. Если показано **Ожидает MCP-сессию — подключить сейчас**, нажмите **Подключить сейчас**.
5. Если MCP подключился, но инструменты не работают, нажмите **Проверить подключение** и проверьте журнал диагностики.

Ошибка `Gitora session bridge not found. Open Gitora and login first.` означает, что MCP-сервер не нашёл активную сессию Gitora. Сначала откройте приложение и войдите в GitHub.

### В списке MCP нет нужных инструментов

Закройте ИИ-клиент, исправьте конфигурацию, снова запустите Gitora и затем заново запустите ИИ-клиент. MCP-инструменты объявляются при старте сервера, поэтому изменение файла конфигурации без перезапуска не применяется.

### Не скачивается архив или asset

Откройте **Настройки** и проверьте папку загрузок. Для архива коммита сначала выберите полный коммит в графе, затем нажмите **Скачать эту версию**.

## Безопасность

- Никому не отправляйте Personal Access Token.
- Не вставляйте токен в промпты, README, issue, Pull Request или конфигурацию MCP.
- MCP не читает токен из открытого файла: запросы выполняет запущенная Gitora.
- Выход через **Отключить GitHub** прекращает доступ MCP к GitHub.
- Удаление репозитория и веток необратимо — всегда проверяйте подтверждение.
- Write-инструменты MCP могут менять данные GitHub. Используйте их только в доверенном ИИ-клиенте и начинайте с тестового репозитория.
