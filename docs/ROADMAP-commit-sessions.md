# Сессии коммитов: запуск версии в изолированной VM (ROADMAP)

Статус: проект, не реализовано. Ветка: `feature/commit-sessions`.

## Идея

Клик по коммиту в графе → кнопка «Запустить эту версию» → Gitora поднимает
одноразовую виртуалку, собирает внутри приложение на этом коммите и показывает
его окно. Пока окно VM открыто — сессия жива. Закрыл окно — виртуалка и все её
данные исчезают, на хосте не остаётся ни мусора, ни кэшей сборок.

Ключевые решения (из обсуждения):
- Версии = **коммиты**, релизы не интересуют.
- Хранение = **как хранит GitHub**: хост скачивает архив коммита (`download-archive`
  уже умеет) и пробрасывает его в VM через общую папку. **Токен в VM не попадает.**
- Файл запуска указывает пользователь (дефолт запоминается на репозиторий).
- VM «просто запускает приложение», глубокого менеджера процессов нет.

## Выбор рантайма

| Вариант | Вердикт |
|---|---|
| Windows Sandbox | **Основной.** Точно ложится на «закрыл = стёрлось», встроен в Windows, своё окно. Минусы: только Pro/Enterprise, нет снапшотов (тулчейн ставится при каждом старте), слабая изоляция GPU. |
| Docker Desktop | Запасной для headless-сборок/логов. GUI-приложения в контейнерах на Windows — боль, не цель. |
| Hyper-V постоянная VM | Против идеи: требует ручного обслуживания снимков и чистки. |
| Изоляция процессом (Job Objects) | Не VM, мусор сборки остаётся на хосте. Отклонено. |

Если Sandbox недоступен (Windows Home), Gitora честно говорит об этом и предлагает Docker/отмену.

## Фазы

### 0. Spike (валидация, без UI)
- Поднять Sandbox через `.wsb` с `MappedFolder` хоста и `LogonCommand`.
- Внутри: распаковать архив коммита, поставить .NET SDK (или взять готовый образ),
  `dotnet build`, запустить GUI-приложение, увидеть его окно.
- Замер: время холодного старта, память, работает ли сеть к github/gitea.
- Выход фазы: GO/NO-GO по Sandbox + цифры стартового времени.

**Итог спайка (2026-09-08, Windows 10 Pro 19045, verdict: GO):**
- Sandbox включается фичей `Containers-DisposableClientVM` (нужны админ-права + ребут).
- `.wsb` с `MappedFolder` + `LogonCommand`: работает, двусторонняя общая папка,
  маркер из VM виден хосту. Загрузка песочницы ~30–60 с.
- `winget` в образе Sandbox **отсутствует** — ставить SDK через `dotnet-install.ps1`
  (https://dot.net/v1/dotnet-install.ps1), сеть внутри есть.
- Холодный старт: SDK 10.0.400 (300 МБ, скачивание+распаковка) ~4.3 мин;
  `dotnet build -c Release` тестового WinForms — 5.26 с; `MiniApp.exe` жив
  (виден в tasklist, окно на экране). Вся сессия ~4.5 мин.
- Вывод для фазы 2: качать SDK каждый раз — главный налог. Решение: хост качает
  SDK один раз и пробрасывает папку в Sandbox read-only (`DOTNET_ROOT`),
  либо закэшированный VHDX. Тогда холодный старт ≈ загрузка + сборка (~1 мин).
  Проверено живьём на фазе 1: маппинг хостового `C:\Program Files\dotnet`
  read-only + `PATH`/`DOTNET_ROOT` в provision — установка SDK скипается,
  сборка+запуск GUI за **40 с** против 4.5 мин холодного старта.

### 1. Модель сессии + IPC
- Сущность `CommitSession`: `{ id, repo, sha, launchFile, vmId, state }`.
- IPC: `session:start { owner, repo, sha, launchFile }`, `session:stop { id }`,
  `session:list`; состояния `starting|running|stopping|gone`.
- Файл запуска: автодетект (`.slnx`/ главный `.csproj`) + ручной выбор + дефолт
  на репозиторий в `localStorage`.
- Архив коммита: переиспользовать `app:download-archive` во временную папку,
  проброшенную в Sandbox. Очистка после стопа.

**Итог фазы 1 (реализовано, без UI):** `electron/commitSessions.cjs` (валидация,
автодетект runnable-проектов, генерация `.wsb`/provision-скрипта) + реестр и IPC
`session:start/stop/list` в `main.cjs` + контракт в `preload`/`types`.
Ограничение: одна живая сессия за раз (лимит ОС). Живой прогон песочницы —
на фазе 3 (Gitea был недоступен в момент dry-run, скачивание архива проверено
ранее через тот же кодовый путь `download-archive`).

### 2. Провижининг внутри VM
- Стартовый скрипт: распаковать архив → `dotnet build -c Release` → запустить
  указанный бинарь. Логи сборки вернуть на хост (файл в общей папке → тост/панель).
- `.wsb`-конфиг: лимиты CPU/RAM, тумблер сети, таймаут автостопа.
- Параллельные сессии: кап (по умолчанию 2), каждая в своей песочнице.

### 3. UI
- Кнопка «Запустить эту версию» в DetailPanel выбранного коммита + выбор файла запуска.
- Панель «Запуски»: список живых сессий (репо, короткий SHA, время), кнопка
  «Остановить», индикатор сборки (спиннер → running/error с логом).
- Ошибки сборки показываются текстом лога, а не молчаливым падением.

### 4. Безопасность и лимиты
- Токены/сессии хоста в VM не пробрасываются (только архив исходников).
- Подтверждение перед стартом, если сессия уже есть; защита от запуска
  `latest.yml`/подозрительных бинарей не из сборки (запускаем только то, что
  собрали сами внутри).
- Gitea: тот же поток через нормализованный слой провайдера.

## Риски

- Sandbox есть не везде (Home) и требует включённой виртуализации в BIOS.
- Холодный старт с установкой SDK — минуты; mitigation: закэшированный VHDX
  с предустановленным SDK или договорённость о долгой первой сборке.
- Приватные зависимости/NuGet-источники с auth внутри чистой VM не встанут —
  честная ошибка с логом, не молчание.
- Антивирусы любят свежесобранные exe — ожидать ложные срабатывания.

## Критерии готовности

- Коммит HardGas/Gitora собирается в Sandbox и показывает окно за приемлемое время.
- Закрытие окна = ноль следов на хосте (кроме лога сборки, если включён).
- Два живых запуска разных коммитов не мешают друг другу.
- `vitest` + `tsc` зелёные, README обновлён.
