# Gitora — Новая версия

## Главное изменение

Смотри, в новой версии Gitora мы сделали приложение спокойнее и безопаснее в ежедневной работе с GitHub. Раньше MCP-сервер и Electron использовали сессию по-разному, а загрузки принимали внешние адреса почти без проверки. Мы решили закрыть эти места, чтобы Gitora оставалась удобным окном в GitHub и при этом меньше зависела от случайных или подменённых входных данных.

---

## Новая функция 1

### Безопасная связь с MCP

Что добавили:

MCP теперь работает через локальный защищённый мост Gitora и использует ту же активную GitHub-сессию, что и само приложение.

Зачем:

Раньше отдельному MCP-процессу было сложнее безопасно получить доступ к текущей сессии. Теперь Personal Access Token не копируется в MCP и не записывается в открытый файл.

Как работает:

Gitora хранит сессию в защищённом хранилище Electron. MCP обращается к локальному мосту, а запрос к GitHub выполняет само приложение. Поэтому после выхода из Gitора MCP тоже перестаёт получать данные.

Как проверить:

1. Запустить Gitora и войти в GitHub.
2. Подключить MCP по инструкции из README.
3. Попросить ИИ показать репозитории или коммиты.
4. Выйти из Gitora и повторить запрос — доступ должен прекратиться.

---

## Новая функция 2

### Защищённые загрузки и запросы

Что добавили:

Gitora теперь проверяет адреса release-файлов, переходы по редиректам, номера PR и issue, а также SHA коммита при скачивании archive.

Зачем:

Раньше значение из интерфейса можно было передать в сетевой запрос почти напрямую. Мы решили проверять такие данные заранее, чтобы приложение не обращалось к случайным адресам и не строило некорректные GitHub-запросы.

Как работает:

Для release assets разрешены только HTTPS-ссылки GitHub. Если GitHub перенаправляет загрузку на другой адрес, каждый переход проверяется отдельно. Номера PR и issue принимаются только в виде положительных чисел, а archive — только по полному SHA коммита.

Как проверить:

1. Открыть обновления Gitora и выбрать release asset.
2. Убедиться, что файл скачивается с GitHub.
3. Открыть PR, issue или архив коммита.
4. Некорректные адреса и параметры должны быть отклонены до запроса.

## Что стало лучше

- ✅ MCP использует актуальную сессию Gitora.
- ✅ Personal Access Token не передаётся MCP и не хранится в открытом виде.
- ✅ Загрузки release-файлов стали предсказуемее и безопаснее.
- ✅ Ошибочные номера PR/issue и SHA больше не попадают напрямую в URL.
- ✅ Основные сценарии подтверждены тестами, сборкой и Electron smoke-проверкой.

## Что дальше

Дальше можно добавить поддержку веток с именами вроде `feature/my-change`, подключить настройку количества загружаемых коммитов и обновлять граф сразу после операций с ветками. Также полезно ввести жёсткие ограничения размера больших загрузок и улучшить обработку устаревших запросов README.
